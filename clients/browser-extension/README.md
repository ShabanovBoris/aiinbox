# AIInbox Capture для Chromium

Расширение Manifest V3 сохраняет URL текущей страницы или выделенный текст в
существующий PM-18 API. Оно отвечает только за браузерный ввод, локальную очередь
повторов и HTTP-транспорт. Обработка, извлечение, анализ и каноническое состояние
Item остаются на сервере AIInbox.

## Архитектура

```text
popup / контекстное меню
        ↓ явное действие пользователя
валидация и локальная очередь service worker
        ↓ POST /v1/items с тем же Idempotency-Key при повторах
PM-18 API → canonical Item → существующий ProcessingWorker
        ↓ GET /v1/items/{id}
popup показывает READY / FAILED / промежуточный статус
```

Service worker — единственный владелец мутаций очереди, сетевых запросов и
учётных данных. Popup может показать заголовок вкладки как локальное превью, но
передаёт серверу только URL, заметку, явно введённую пользователем, либо
выделенный текст вместе с URL страницы. HTML, скриншоты и заголовок вкладки не
отправляются.

## Разрешения и безопасность

Обязательные разрешения:

- `activeTab` — временный доступ к активной вкладке после нажатия на расширение
  или пункт контекстного меню;
- `contextMenus` — пункты сохранения страницы и выделения;
- `storage` — очередь и настройки в хранилище расширения;
- `alarms` — восстановление повторов после остановки service worker.

Доступ к серверу объявлен как optional host permission и запрашивается только
после нажатия Save/Test в настройках. Chromium ограничивает такой шаблон схемой,
хостом и портом; перед добавлением Bearer заголовка клиент отдельно проверяет,
что URL запроса имеет origin настроенного API.

Нет content script, постоянного доступа ко всем страницам, `tabs`, `scripting`,
`webRequest`, cookies, истории браузера, удалённого кода или аналитики. Запросы
используют `credentials: omit` и `redirect: error`; сервер CORS не меняется.

Токен хранится только в `chrome.storage.local`, ограниченном контекстами самого
расширения через `setAccessLevel(TRUSTED_CONTEXTS)`. Popup и Options получают
только признак `token_configured`, не значение секрета. Это предотвращает доступ
страницам и будущим content scripts, но не является шифрованием от полностью
скомпрометированного browser profile или учётной записи ОС.

Удалённый API обязан использовать HTTPS. HTTP допускается только для `localhost`
и `127.0.0.1`. Расширение не отключает и не обходит предупреждения сертификата.

## Offline очередь и приватность

Перед сетью service worker сохраняет запрос, UUID/idempotency key, время и
счётчик попыток. Повтор использует тот же ключ и то же тело. Сетевые ошибки,
408, 429 и 5xx повторяются с ограниченной задержкой; максимум — восемь
автоматических попыток. 401 блокирует отправку до сохранения/проверки новых
учётных данных; 409, 413, 422 и прочие постоянные 4xx становятся ошибками,
которые пользователь может удалить в Options.

Очередь ограничена 100 записями и 1 000 000 символов текста/заметок. Она не
вытесняет старые запросы автоматически. Если API origin меняется, уже созданные
записи остаются привязаны к старому серверу; расширение не отправит неоднозначный
повтор новому серверу, где тот же ключ мог бы создать второй Item. Вернув старый
origin и введя его токен, пользователь может возобновить такую очередь. После
`202 Accepted` текст, заметка и idempotency key удаляются локально; остаётся
только ограниченная запись статуса Item.

## Требования сервера и установка

Нужен запущенный AIInbox с включённым PM-18 API. Настройте `.env` без сохранения
токена в репозитории:

```dotenv
HTTP_API_ENABLED=true
HTTP_API_HOST=127.0.0.1
HTTP_API_PORT=8080
HTTP_API_TOKEN=<strong secret>
HTTP_API_USER_TELEGRAM_ID=<your numeric Telegram user id>
```

Для нового токена можно использовать `openssl rand -hex 32`. Операционная
настройка API описана в [RUNBOOK](../../docs/RUNBOOK.md#optional-http-api).

Установка локальной unpacked-версии:

1. Запустите AIInbox с включённым PM-18 API.
2. Откройте `chrome://extensions` и включите Developer mode.
3. Нажмите **Load unpacked** и выберите `clients/browser-extension/`.
4. Откройте Options у AIInbox Capture.
5. Введите API origin (`http://127.0.0.1:8080` для локального сервера) и Bearer token.
6. Сохраните настройки и подтвердите запрошенный доступ к этому серверу.
7. Нажмите **Test connection**. Проверяются `/healthz` и авторизованный
   `GET /v1/items?limit=1`.

Для удалённого сервера задайте HTTPS reverse proxy перед HTTP listener, как
описано в RUNBOOK. Не публикуйте Bearer API напрямую по HTTP.

## Сборка и проверка

Сборщик и runtime npm-зависимости не нужны. Папка напрямую загружается в Chromium.

```bash
npm --prefix clients/browser-extension run check
npm --prefix clients/browser-extension test
```

Создать ZIP только из runtime-файлов:

```bash
cd clients/browser-extension
zip -r aiinbox-capture-0.1.0.zip manifest.json popup.html options.html src icons
```

Команда не включает тесты, README и `package.json`. Chrome Web Store публикация
не входит в PM-33 V1.

## Известные ограничения

- Chromium 120+; Firefox в V1 не поддерживается.
- Сохраняются только HTTP(S) URL и выделенный текст; страницы браузера и
  локальные файлы не поддерживаются.
- После 30 минут фоновое обновление статуса останавливается; открытие popup
  запрашивает актуальный статус ещё раз.
- Ручной discard необратимо удаляет выбранную локальную capture-запись, но не
  удаляет уже созданный серверный Item.
