# Возможности Telegram-бота

Практическая справка по тому, что умеет Personal AI Inbox и как этим пользоваться.
Встроенная команда `/help` даёт короткую памятку; этот документ описывает
полную пользовательскую поверхность и текущие ограничения.

## Быстрый старт

Обычный сценарий максимально короткий:

```text
отправить что-нибудь боту
→ бот сохранит Item
→ фоновые workers извлекут содержимое и проанализируют его
→ бот пришлёт карточку с заголовком, выводом и действиями к источнику
```

Сообщение можно также просто переслать боту из Telegram — для поддерживаемых
типов бот сохранит доступную информацию об источнике автоматически.

Для работы Telegram user id должен входить в `ALLOWED_TELEGRAM_USER_IDS`.
Пользователи вне allowlist молча игнорируются.

## Что можно отправлять

### Обычный текст

Любое сообщение без команды и без URL сохраняется как один `TEXT` Item.

Пример:

```text
Разобраться, как устроены structured outputs и где они пригодятся в Android-проекте
```

После обработки по умолчанию бот показывает заголовок и короткий вывод. Категория,
тип, приоритет, интерес и пояснения анализа доступны по кнопке `ℹ️ Детали`.

### Веб-ссылки

Можно отправить одну или несколько ссылок в одном сообщении.

```text
Посмотреть применимость к нашему проекту
https://example.com/article-1
https://example.com/article-2
```

Все ссылки остаются внутри одного Item. Каждая ссылка извлекается отдельно, текст
сообщения сохраняется как пользовательский контекст, а итоговый summary строится
один раз по всему доступному содержимому. Для нескольких ссылок summary должен
учитывать содержательную часть каждой успешно разобранной ссылки, даже если темы
различаются. Один URL в разных сообщениях не склеивает эти сообщения в один Item.

Бот скачивает только публично доступные страницы. Доступ к локальным/private
сетям блокируется. Browser/Playwright fallback сейчас отключён: если обычное
безопасное извлечение страницы не даёт достаточно текста, Item завершится
контролируемой ошибкой.

### YouTube

YouTube-ссылка автоматически определяется как `YOUTUBE`.

```text
Посмотреть и решить, стоит ли применять
https://www.youtube.com/watch?v=...
```

Пайплайн пытается получить субтитры на настроенных языках, а если пригодных
субтитров нет — скачивает аудио и делает STT. При доступной vision-модели бот
также может извлечь representative frames и добавить визуальный контекст.

Текущие дефолтные ограничения:

- длительность YouTube — до 7200 секунд (2 часа);
- скачиваемое YouTube-аудио — до 50 MB;
- скачиваемое видео для visual analysis — до 50 MB;
- файл субтитров — до 2 MB;
- для visual analysis нужен `ffmpeg` и настроенная vision-модель.

Если visual analysis недоступен или падает, успешный transcript всё равно может
быть обработан как `TRANSCRIPT_ONLY`. Если же у видео нет audio track или STT не
получил текст, бот попробует анализ только по кадрам; такой результат будет
`VISUAL_ONLY` и появится, только если visual analysis успешно завершится.

У готового YouTube Item есть кнопка `📩 Прислать YouTube`. Она ставит отправку
исходного ролика в очередь; ролик придёт ответом на сообщение со ссылкой. Если в
одном Item несколько видеоисточников, у каждого будет своя кнопка. Лимит отправки
в Telegram — до 50 MB. Если видео превышает этот лимит, бот попробует отправить
только аудио и укажет это в подписи. Если аудио тоже слишком большое, бот сообщит
об этом отдельно.

### Instagram Reels

Можно отправить ссылку на конкретный Reel:

```text
https://www.instagram.com/reel/ABC123/
```

Поддерживается публичное извлечение через yt-dlp. Доступный звук транскрибируется
через настроенный STT provider; при включённой vision-модели бот анализирует
representative frames. Подпись сохраняется отдельно как описание и не считается
транскриптом. Если речи нет и подпись содержательна, Item может быть обработан как
`CAPTION_ONLY`; если доступны только кадры — как `VISUAL_ONLY`.

Лимиты по умолчанию: 2 часа и 50 MB для audio и video. Instagram может требовать
cookies или временно ограничивать доступ; бот сохранит ссылку и покажет
контролируемую ошибку. Для необязательной ручной настройки cookie file см.
[RUNBOOK](RUNBOOK.md). Stories, профили и private-account обход не поддерживаются.
У готового Reel есть отдельная кнопка `📩 Прислать Reel`; нажатие
повторно получает ролик и отправляет его ответом на сообщение со ссылкой. Лимит
отправки в Telegram — до 50 MB.
Если Reel слишком большой для отправки видео, бот попробует отправить только
аудио и прямо сообщит об этом в подписи. Если аудио тоже слишком большое, бот
сообщит об этом отдельно.

### Голосовые сообщения

Telegram voice message можно отправить напрямую боту. Оно сохранится как
`VOICE`, будет скачано worker-ом, транскрибировано и пройдёт через тот же анализ,
что текст и ссылки.

### Аудиофайлы

Telegram audio также поддерживается и сохраняется как `AUDIO`.

Дефолтный лимит voice/audio — 20 MB. Если файл больше, бот сохраняет метаданные,
но не скачивает файл и сообщает об ошибке размера.

Telegram video также поддерживается: бот транскрибирует звуковую дорожку и, если
vision-модель доступна, добавляет информацию из representative frames. Caption и
ссылки рядом с видео анализируются в том же Item. Если видео не обработалось, но
есть содержательный caption или рабочая ссылка, Item всё равно завершается
частичным анализом. Если у видео нет аудиодорожки, но vision-анализ кадров успешен,
бот обработает ролик по кадрам и пометит результат как `VISUAL_ONLY`.

### Документы

Можно отправить или переслать PDF, TXT, Markdown (`.md`/`.markdown`) и DOCX.
Подпись и URL рядом с документом остаются в том же Item; для прямого сообщения
подпись также задаёт пользовательский контекст.

Из PDF извлекается выделяемый текст с сохранением порядка страниц. Сканированные
PDF и документы без извлекаемого текста завершаются понятной ошибкой: OCR не
поддерживается. Для DOCX читаются абзацы и таблицы; `.doc`, `.docm`, архивы,
таблицы и презентации не поддерживаются. Размер файла и извлечённого текста
ограничен настройками `MAX_DOCUMENT_BYTES` и `MAX_DOCUMENT_TEXT_CHARS`.

Ссылка, фактически возвращающая PDF, проходит тот же защищённый web downloader,
что и обычные страницы: проверяются публичный адрес, каждый redirect и общий
download limit. `.pdf` URL, возвращающий HTML, не считается PDF-документом.

### Пересланные сообщения

Можно пересылать боту обычный текст, статьи/YouTube-ссылки, voice, audio, video
и поддерживаемые документы.
Forwarding не меняет тип Item: пересланная статья остаётся `WEB`, YouTube —
`YOUTUBE`, голосовое — `VOICE`, видео — `VIDEO`, документ — `DOCUMENT`.

Любое входящее Telegram-сообщение считается одной единицей контента. Несколько
ссылок, voice/audio/video/documents и caption не создают отдельные Items: это дочерние
sources одного Item. Каждый source извлекается отдельно, после чего бот делает
один общий анализ всего доступного содержимого.

Если канал прислал пост как фото с подписью, бот извлекает URL из caption, включая
скрытые Telegram `text_link`, и сохраняет caption целиком как source content.
Caption анализируется даже без URL. Само изображение пока не анализируется; фото
без caption остаётся неподдерживаемым.

Если Telegram передал origin, Item сохраняет доступный provenance: тип origin,
имя/username источника, исходное время и для channel-forward — message id.
Недостающие поля бот не угадывает.

Текст исходного автора не считается вашей заметкой. Он сохраняется целиком как
source content; для forwarded URL/media передаётся в анализ как source context
отдельно от `user_note`.

Для публичного канала появляется `↗ Оригинальный пост`, только если Telegram дал
и public username канала, и id исходного сообщения. Для private/hidden origin
ссылка не строится.

Результат обработки VIDEO приходит ответом на сообщение с видео. Нажмите на
заголовок ответа, чтобы вернуться к отправленному или пересланному в бот видео.
Telegram не предоставляет постоянную ссылку на отдельное сообщение в личном
чате с ботом; для публичного поста канала доступна отдельная кнопка оригинала.

### Что не поддерживается

Video note и direct image не обрабатываются. Instagram поддерживается только для
конкретных Reel URL; extraction зависит от текущего поведения yt-dlp и Instagram.
Если Telegram прислал видео как `Document` (`video/*` или распознаваемое
video-расширение), оно всё равно идёт в
VIDEO pipeline. Обычный Telegram video и forwarded video используют transcript
и optional vision. Из документов принимаются только PDF/TXT/Markdown/DOCX.

Если один из поддерживаемых вложенных sources не удалось извлечь, но у сообщения
остался текст или другой успешный source, результат помечается как частичный,
вместо потери всего Item.

## Что приходит после анализа

В READY Item сохраняются:

- заголовок;
- категорию;
- тип Item;
- приоритет от 0 до 100;
- ручной уровень интереса от 1 до 3 (по умолчанию 2);
- краткое резюме;
- следующее действие;
- объяснение, почему Item получил такой приоритет.

Типы Item:

- `ACTION` — конкретное действие;
- `LEARN` — изучить;
- `READ` — прочитать;
- `WATCH` — посмотреть;
- `IDEA` — идея;
- `REFERENCE` — справочный материал;
- `SOMEDAY` — когда-нибудь.

Финальный priority score вычисляется кодом из структурированных LLM-сигналов,
а не принимается как произвольная оценка модели. По умолчанию Telegram показывает
только подтверждение сохранения, title, summary и важное предупреждение о неполном
анализе. Остальные поля открываются по запросу через `ℹ️ Детали`.

## Действия с Item

Основная карточка показывает кнопки источника/повторной отправки (если они есть) и
`••• Ещё`. Для нескольких источников кнопка `🔗 Источники` открывает ограниченный
список с отдельными действиями. URL-кнопки называют направление: например,
`↗ YouTube`, `↗ Instagram Reel`, `↗ GitHub`, `↗ Статья — example.com` или
`↗ Документ — example.com`.

`••• Ещё` открывает управление Item. Переходы по меню только перечитывают Item и
меняют Telegram-разметку; они не создают Events и не меняют данные.

### Готово

`✅ Готово` переводит Item в `DONE`.

### Later

`⏰ Позже` предлагает:

- завтра;
- через неделю;
- через месяц;
- отменить выбор.

Item переходит в `SNOOZED`, а reminder хранится в SQLite и переживает restart.
Когда срок наступит, бот вернёт Item пользователю с учётом quiet hours.

### Archive

`🗄 Архив` переводит Item в `ARCHIVED`.

### Интерес

Под `⭐ Интерес` доступны уровни `1 — Низкий`, `2 — Обычный`, `3 — Высокий`.
Текущий уровень помечен галочкой. Выбор сохраняет существующий сигнал интереса и
не меняет priority score.

### Retry

Если обработка завершилась `FAILED` или `READY/PARTIAL` из-за failed child source,
на карточке показывается `🔁 Повторить`. Постоянная ошибка источника не получает
бесполезную кнопку повтора. Повторная обработка сохраняет достигнутые checkpoints:
успешные sources не извлекаются заново, failed sources пробуются повторно, а общий
analysis пересобирается из актуального набора доступного контента.

### Обратная связь и исправления

У READY Item, включая частичный результат, в `🛠 Обратная связь` доступны:
`👍 Полезно`, `👎 Не моё`, исправление категории/типа, сигнал приоритета выше/ниже
и `📝 Summary неверный`.

Полезно и Не моё сохраняют отдельные сигналы. Они не меняют уровень интереса,
приоритет или состояние Item. Done, Later и Archive остаются отдельными
действиями жизненного цикла.

В меню обратной связи можно выбрать категорию или тип, сообщить, что приоритет должен
быть выше/ниже, либо отметить неверное резюме. Список категорий содержит до 20
самых часто встречающихся категорий пользователя; выбрать можно только уже
существующую категорию. Исправление категории сразу меняет результат /category,
а исправление типа — доступность Item в /today. Эти исправления не запускают
повторный анализ и не пересчитывают приоритет. После изменения карточка остаётся в
меню обратной связи; новую категорию или тип можно посмотреть в `ℹ️ Детали`.

### Детали

`ℹ️ Детали` read-only показывает доступные category, локализованный тип, priority,
interest, полноту анализа, следующее действие и причину приоритета. Пустые поля
опускаются.

## Команды

### `/start`

Проверяет доступ и отвечает, что бот готов принимать данные.

### `/help`

Показывает краткую встроенную справку по командам.

### `/today`

Показывает короткий список наиболее приоритетных активных READY Items типов:

```text
ACTION
LEARN
READ
WATCH
```

По умолчанию возвращается до 3 Items. `IDEA`, `REFERENCE` и `SOMEDAY` в
`/today` не попадают.

Пример ответа:

```text
Сегодня:
1. Разобрать статью про agents — 82/100
   ~20 мин
   Выписать применимые идеи
```

### `/attention [1-5]`

Показывает Items, которые Attention Engine считает наиболее заслуживающими
внимания сейчас; ничего автоматически не отправляет. По умолчанию бот выводит
до 3 отдельных карточек, можно запросить от 1 до 5. Карточка содержит title,
короткий preview summary и компактные действия к источникам; score, возраст и
ranking reason скрыты. Жизненный цикл и обратная связь доступны через `••• Ещё`.
Успешно показанные Items учитываются при следующем ручном `/attention`, чтобы
снизить повторные показы.

### `/inbox`

Показывает последние Items, максимум 20.

Важно: текущая реализация не фильтрует `/inbox` только по `ACTIVE`, поэтому в
список могут попадать также `DONE`, `SNOOZED` и `ARCHIVED` Items.

### `/category`

Без аргумента показывает существующие категории и количество Items:

```text
/category
```

С аргументом показывает до 20 Items указанной категории:

```text
/category Обучение
```

Категории создаются анализатором динамически, это не жёсткий enum.

### `/search <запрос>`

Полнотекстовый поиск по сохранённым данным:

```text
/search compose recomposition
```

Поиск учитывает:

- title;
- summary;
- пользовательскую заметку;
- tags;
- извлечённый текст страницы;
- transcript, извлечённый текст документов и другой сохранённый content.

В поиск входят в том числе `DONE` и `ARCHIVED` Items. По умолчанию возвращается
до 10 результатов.

### `/ask <вопрос>`

Синтезирует ответ только по уже сохранённым материалам:

```text
/ask Какие варианты локальных LLM на Android я сохранял?
```

Бот сразу подтверждает запрос, затем присылает один ответ с источниками и
кнопками открытия, если у источника есть сохранённый HTTP(S) URL. Ответ строится
в языке из `/profile`; исходный текст не переводится и внешние страницы не
обновляются. Если FTS5 не находит Items, LLM не вызывается. Если найденных
сведений недостаточно, бот прямо сообщает об этом вместо неподтверждённого
ответа. Каждый `/ask` — отдельный вопрос без истории переписки.

Пределы: вопрос — 2000 символов; поиск — до 8 Items по умолчанию, максимум 10;
контекст — не более 6000 символов на Item и 40000 суммарно. `/ask` использует тот
же настроенный `LLM_PROVIDER` и analysis model, что обработка Items.

### `/export [compact|full]`

Отправляет переносимую копию сохранённых данных одним ZIP-файлом:

```text
/export          # compact по умолчанию
/export compact
/export full
```

Бот быстро подтверждает запрос и готовит архив в фоне. `compact` содержит Items,
источники и provenance, профиль, пользовательские настройки, события и историю
напоминаний без длинного сохранённого текста и транскриптов. `full` дополнительно
включает исходный текст, тексты страниц и документов, транскрипты, визуальные
заметки и описания. Полный экспорт может содержать приватные сохранённые тексты и
транскрипты.

Экспорт включает Items во всех lifecycle-состояниях, в том числе завершённые,
архивные и неудачно обработанные. Это переносимый пользовательский формат, а не
SQLite backup и не способ импортировать данные обратно. Архив отправляется через
Telegram; если полный ZIP превышает лимит отправки, бот сообщит об ошибке и
предложит `/export compact`.

### `/profile`

Показывает профиль пользователя, который может содержать профессию, домены,
цели с весами, интересы, ограничения, язык ответа и свободные заметки.

Профиль участвует в анализе новых Items.

### `/profile_update <инструкция>`

Обновляет профиль естественным языком в фоне.

```text
/profile_update Сейчас хочу повысить приоритет изучения AI-агентов и меньше внимания уделять Kubernetes
```

Команда быстро отвечает `Принял. Обновляю профиль…`, а LLM-обновление выполняет
отдельный durable worker. После завершения бот уведомит об изменённых полях.

Изменение профиля не запускает автоматический re-analysis уже сохранённых Items.
Язык ответа для видео можно установить командой
`/profile_update отвечай по-английски`; в `/profile` он показывается кодом,
например `en`. Transcript может быть на другом языке, но итоговые title, summary,
следующее действие и описание кадров будут на языке профиля. Для остальных
источников сохраняется текущий выбор языка по языку контента.

### `/settings`

Показывает настройки уведомлений:

- timezone;
- включён ли daily digest;
- время daily digest;
- quiet hours;
- состояние Attention Manager и выбранную интенсивность.

При первом использовании дефолты такие:

```text
digest: enabled
time: 09:00
quiet hours: 22:30-08:00
```

В сообщении есть кнопка включения/выключения digest.

Изменить timezone:

```text
/settings timezone Europe/Moscow
```

Изменить время digest:

```text
/settings time 09:00
```

Изменить quiet hours:

```text
/settings quiet 22:30-08:00
```

Открыть настройки proactive Attention Manager:

```text
/settings attention
```

Новые пользователи получают Attention Manager включённым с интенсивностью
`3 — Normal`. Для пользователей, существовавших до PM-08, он выключен после
обновления, чтобы не создавать неожиданные уведомления; включить его можно
кнопкой `Attention ON` в `/settings attention`.

В этих настройках отдельно показан `Generic motivation` с кнопкой
`Motivation ON/OFF`. Новые пользователи получают его включённым. Для
существовавших пользователей migration выставляет OFF, если значение ещё не
было задано; это не меняет их Attention toggle. Отключение Generic motivation
оставляет Item-specific proactive reminders доступными, если Attention Manager
включён.

Интенсивность выбирает фиксированную политику:

| Уровень | Режим | Общий дневной лимит уведомлений | Минимальный интервал | Повтор Item |
|---:|---|---:|---:|---:|
| 1 | Calm | 1 | 8 ч | 72 ч |
| 2 | Light | 2 | 5 ч | 48 ч |
| 3 | Normal | 3 | 3 ч | 30 ч |
| 4 | Active | 4 | 2 ч | 20 ч |
| 5 | Aggressive | 6 | 90 мин | 12 ч |

Общий лимит включает daily digest, proactive reminders и generic motivation.
Generic motivation дополнительно ограничена: Calm — 0 в день, Light/Normal/
Active — до 1, Aggressive — до 2. Snooze resurfacing не расходует общий лимит,
но запускает минимальный интервал. Любое автоматическое Attention-уведомление
уважает quiet hours; proactive reminder требует актуального PM-07 attention
score не ниже 60. На уровнях 1–3 подходящий Item-specific reminder имеет
приоритет; на уровнях 4–5 proactive и generic intervention чередуются, когда
оба доступны. В одном цикле отправляется не более одного Attention intervention.
Отключение и повторное включение не создают очередь пропущенных напоминаний.

Generic motivation отправляет только короткие русские сообщения по текущим
фактам AIInbox: давно лежащие важные/интересные Items, короткие actionable
задачи, дневной прирост backlog, текущую серию Done или завершения за последние
семь локальных дней. Случайных цитат, оценок продуктивности, профилирования,
LLM-текста и Item-кнопок у такого сообщения нет. `👍 Ок` только закрывает
обратную связь и не записывает положительную метрику; `👎 Меньше таких`
подавляет этот вид nudge на семь дней, не выключая настройку целиком.

Timezone должен быть валидным IANA timezone, время задаётся в формате `HH:MM`.

## Уведомления

### Результат обработки

После перехода Item в `READY` бот присылает результат. Если обработка завершилась
ошибкой, приходит failure-сообщение с возможностью Retry.

Immediate notifications проходят через durable outbox: намерение отправить
сообщение хранится в SQLite и переживает restart процесса.

### Daily digest

Если digest включён, бот один раз за локальный день формирует список через ту же
логику, что `/today`. Время задаётся `/settings time ...`.

Digest не отправляется внутри quiet hours; доставка откладывается до допустимого
времени.

### Snooze reminder

`Later` создаёт отдельный durable reminder. После истечения срока Item снова
показывается пользователю. Quiet hours также учитываются.

### Proactive Attention

Когда Attention Manager включён, ReminderWorker периодически выбирает один
подходящий Item через PM-07 ranking и применяет интенсивность, локальный дневной
лимит, интервал и cooldown. В одном цикле пользователю отправляется не более
одного proactive reminder. Карточка предлагает `⏰ Позже`, `✅ Готово`,
`🙈 Не сейчас` и `👎 Меньше таких`, а также доступные source actions. Archive,
ручной интерес и PM-05 обратная связь остаются на обычных карточках Item.
После успешной отправки Reminder и его Event учитываются в истории; неудачная
отправка не создаёт `REMINDER_SENT` и не расходует бюджет.

Карточка может дополнительно показать одну сильную мысль из сохранённого
материала. Она строится только по уже сохранённому source content; если
подтверждённого hook нет или provider недоступен, карточка отправляется с
прежним разделом «Почему сейчас». Когда hook относится к одному источнику в
составном Item, соответствующая ссылка или действие источника показывается
первым. Ручной `/attention` остаётся быстрым детерминированным preview.

Реакции относятся к конкретному Reminder. `Готово` фиксирует обычный `DONE` и
`REMINDER_DONE`; `Позже` фиксирует `SNOOZED` и `REMINDER_SNOOZED`. `Не сейчас`
не меняет Item и откладывает следующее proactive напоминание минимум на 24 часа.
`Меньше таких` не архивирует Item и не меняет его интерес или приоритет.
Кнопка отправки YouTube/Reel через бота даёт наблюдаемый `REMINDER_OPENED`;
переход по обычной URL-кнопке Telegram бот отследить не может и не записывает.

## Типичные сценарии

### Быстро сохранить мысль

```text
Сделать прототип локального semantic search для заметок
```

Ничего классифицировать вручную не нужно.

### Сохранить статью с контекстом

```text
Проверить, можно ли применить этот подход в PhotoSearch
https://example.com/article
```

Заметка сохранится вместе с Item и будет участвовать в анализе и поиске.

### Разобрать несколько ссылок

```text
Сравнить подходы
https://example.com/a
https://example.com/b
https://example.com/c
```

Получится один Item: бот извлечёт все три страницы и сделает один общий анализ.
В итоговом title/summary должны быть представлены все три содержательные части,
а не только первая ссылка.

### Надиктовать задачу

Отправить voice message вместо текста. Бот транскрибирует его и обработает как
обычный входящий материал.

### Сохранить длинное YouTube-видео

Прислать ссылку на YouTube. Бот постарается использовать subtitles, иначе STT,
а при настроенном vision — добавит visual context.

### Выбрать, чем заняться сейчас

```text
/today
```

После выполнения нажать `Done`, либо `Later`, если Item нужно вернуть позже.

Для динамического списка с учётом возраста, интереса и предыдущих показов:

```text
/attention
```

### Посмотреть, как прошла неделя

```text
/weekly
```

Команда по запросу показывает поток добавленных, завершённых и архивированных
Items, текущий actionable backlog, старые Items, темы недели, сырые результаты
proactive Attention reminders и до трёх детерминированных следующих шагов.
Отчёт охватывает последние семь локальных календарных дней пользователя,
включая сегодня; возраст Items считается по прошедшему времени. Категории для
созданий и завершений отражают текущую категорию Item.

Команда только читает факты для обзора: она не меняет Items, напоминания,
профиль или настройки, не записывает события показа, не использует LLM и не
присылает автоматический еженедельный push.

### Найти старый материал

```text
/search structured outputs android
```

Поиск работает и по содержимому сохранённых страниц/transcripts, а не только по
названию Item.

### Сопоставить сохранённые материалы

```text
/ask Сравни подходы к локальным LLM на Android, которые я сохранял
```

Ответ синтезируется из найденных Items и показывает проверенные названия
источников. `/ask` не ищет в интернете и не превращает ответ в новый Item.

### Изменить приоритеты системы

```text
/profile_update В ближайшие месяцы главный фокус — AI agents, Android ML и backend
```

Следующие Items будут анализироваться с учётом обновлённого профиля.

## Важные ограничения

- доступ к боту ограничен Telegram allowlist;
- direct/forwarded Telegram video поддерживаются, включая video-as-document;
- direct image и video note пока не обрабатываются;
- документы ограничены PDF/TXT/Markdown/DOCX и настройками file/text size;
- OCR, `.doc`/`.docm`, таблицы, презентации и произвольные архивы не поддерживаются;
- web extraction ограничен публичной сетью и download cap 5 MB;
- URL PDF использует тот же web download cap 5 MB и SSRF-защиту;
- voice/audio ограничены 20 MB по умолчанию;
- YouTube ограничен 2 часами и media caps из конфигурации;
- Instagram Reel ограничен `INSTAGRAM_MAX_DURATION_SECONDS` и отдельными audio/video caps;
- для OpenRouter long-audio STT и video visual analysis нужен `ffmpeg`;
- без vision-модели YouTube/Telegram video всё равно обрабатываются по transcript;
- вывод Telegram ограничивается 4096 символами, поэтому длинные ответы
  автоматически обрезаются;
- `/inbox` сейчас показывает последние Items независимо от lifecycle state;
- профиль влияет на будущие анализы, но не пересчитывает старые Items;
- semantic/vector search в MVP нет — `/search` использует SQLite FTS5.
- `/ask` использует тот же лексический FTS5 retrieval; он не обновляет источники,
  не использует embeddings и не сохраняет сгенерированный ответ в историю Items.

## Если что-то упало

Если Item перешёл в `FAILED`, сначала используйте `Retry`. Система сохраняет
durable checkpoints и старается продолжить с уже выполненного этапа.

Для диагностики самого приложения, SQLite, workers и migrations предназначен
[RUNBOOK](RUNBOOK.md). Эта страница описывает именно пользовательскую поверхность
Telegram-бота.
